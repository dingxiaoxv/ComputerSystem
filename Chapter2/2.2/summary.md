# §2.2 整数表示

这一节的主线是：**同样的位模式，无符号和补码两种编码只差最高位的权重符号**。这个微小差别衍生出所有有符号 / 无符号行为差异——范围不对称、`INT_MIN` 取反失败、混合运算时的隐式转换陷阱。

---

## 两种编码的本质差异

**🎯 唯一的不同点：最高位权重**

```
位模式:   1    0    0    0
         ↓    ↓    ↓    ↓
权重:    +8   +4   +2   +1    → 无符号: 8
权重:    -8   +4   +2   +1    → 补码:  -8
```

无符号最高位权重是 $+2^{w-1}$，补码最高位权重是 $-2^{w-1}$。其余所有位完全一样，这是两种编码的唯一区别。

**🎯 数值范围不对称**

以 4 位补码为例：

```
无符号:   0000(0)   ~  1111(15)        16 个值，从 0 起步
补码:    1000(-8)  ~  0111(7)         16 个值，|TMin| = 8 > TMax = 7
```

补码负数比正数多一个——这就是 `INT_MIN` 没有对应正数的根源。

---

## 有符号 ↔ 无符号 转换

**🎯 位不变，解释方式变**

```
位模式    无符号解释    补码解释
 1111        15          -1
 1110        14          -2
 1100        12          -4
 1000         8          -8
 0111         7           7   ← 分界线（TMax）
 0001         1           1
```

规律：

- `0xxx` 开头：两种解释结果相同
- `1xxx` 开头：无符号值 = 补码值 + $2^w$

**⚠️ 混合运算时有符号转为无符号**

C/C++ 的隐式转换规则是**有符号 → 无符号**，不是反方向：

```c
-1 < 0U     // -1 转为 UINT_MAX(4294967295)，结果 false
 2 > -1U    // -1U = UINT_MAX，2 < UINT_MAX，结果 false
```

记法：在转换里有符号是"弱势"的一方。

---

## 扩展与截断

**🎯 扩展规则跟着源类型走**

```c
uint8_t  a = 0b00001010;   //  10
uint16_t b = a;            //  0000 0000 0000 1010  → 10（高位补 0）

int8_t   c = 0b10001010;   // -118
int16_t  d = c;            //  1111 1111 1000 1010  → -118（符号位复制）
```

源类型有符号就符号扩展，源类型无符号就零扩展。这一点和 §3.4 的 `movsbq` / `movzbl` 直接对应。

**🎯 截断丢高位，数值可能改变**

```c
int x = 0x12345678;
char c = x;     // 只保留 0x78 = 120，高位丢弃
```

## INT_MIN 写法的坑

**⚠️ 不能直接写 `int x = -2147483648`**

```c
int x = -2147483648;   // 行为不符合直觉
```

编译器把 `2147483648` 先识别为字面量——它超过 `INT_MAX`，被升级为 `long`；再加负号后类型仍是 `long`；最后赋给 `int` 是截断。结果不是简单的 `INT_MIN`。

正确写法是先用 `INT_MAX` 再减 1：

```c
#define INT_MIN  (-INT_MAX - 1)
```

`<climits>` 里的 `INT_MIN` 就是这么定义的。

## 无符号导致的三个经典 Bug

**🔧 Bug 1：`unsigned` 倒序循环死循环**

```c
for (unsigned i = n - 1; i >= 0; i--)   // i >= 0 对无符号恒为真
    arr[i];
```

**🔧 Bug 2：`strlen` 相减绕回**

```c
// strlen 返回 size_t（无符号）
if (strlen(s) - strlen(t) > 0)   // t 比 s 长时绕回为 UINT_MAX，恒为 true
    puts("s is longer");
```

正确写法：`if (strlen(s) > strlen(t))`，让减法变成比较。

**🔧 Bug 3：长度为 0 时上界绕回**

```c
for (unsigned i = 0; i <= length - 1; i++) { ... }
// length = 0 时 length-1 = UINT_MAX，循环跑 40 亿次
```

## 易错点

- 混合运算时有符号转为无符号，不是反方向，`-1 < 0U` 为 `false`
- `INT_MIN` 不能直接写 `-2147483648`，编译器先把字面量识别为 `long`，结果不符合直觉
- 字面量超过 `INT_MAX` 时默认升级为更大的有符号类型，要无符号必须加 `U` 后缀
- 扩展是符号扩展还是零扩展由**源类型**决定，不是目标类型
- 截断是直接丢高位，符号位会跟着丢，不要假设它会"截到能表示的最大值"
- `size_t` / `unsigned` 做循环计数器时 `i >= 0` 恒为真，倒序循环要么改 `int`，要么用 `i-- > 0` 模式

---

## 工程关联

- `std::vector::size()` 返回 `size_t`，与 `int` 比较会触发 `-Wsign-compare` 警告，本质就是隐式转换在起作用
- Linux 内核大量使用 `u32` / `u64`，无符号绕回在协议处理、计数器场景被有意利用（如 TCP 序列号）
- 网络协议长度字段常用无符号 16 位，但解析时若直接和 `int` 相减再判断，可能踩绕回陷阱
- GCC `-Wconversion` 能定位有符号 / 无符号互相赋值的位置，重构旧代码时是第一道防线
- 安全漏洞里"整数溢出 → 缓冲区溢出"链条经常起于无符号绕回（CVE 中常见模式），分配大小用 `size_t` 时要先验证

## 实验题

**🧪 题 1：观察有符号 → 无符号隐式转换**

```cpp
int a = -1;
unsigned int b = 0;
std::cout << (a < b) << "\n";                // 期望
std::cout << std::hex << (unsigned)a << "\n";
```

要求：

- 预测 `a < b` 的输出
- 编译运行，解释为什么得到 `false`
- 打印 `(unsigned)a` 的十六进制，确认它变成了 `0xFFFFFFFF`

**🧪 题 2：`strlen` 相减的绕回陷阱**

```cpp
const char* s = "hi";
const char* t = "hello";
if (strlen(s) - strlen(t) > 0) std::cout << "s 更长\n";
else                            std::cout << "t 更长\n";
```

要求：

- 预测输出，再运行验证
- 改写为不依赖减法的正确版本
- 用 `std::cout << (strlen(s) - strlen(t))` 打印中间值，理解绕回

**🧪 题 3：`unsigned` 倒序循环死循环**

```cpp
std::vector<int> v = {10, 20, 30};
for (size_t i = v.size() - 1; i >= 0 && i < 100; i--) {
    std::cout << i << " ";
}
```

要求：

- 加 guard 限制最多打印 5 次，观察 `i` 在 0 之后变成什么
- 改写为正确版本：`for (size_t i = v.size(); i-- > 0;)`
- 解释为什么这种模式能解决问题

**🧪 题 4：`INT_MIN` 字面量陷阱**

```cpp
std::cout << (int)-2147483648 << "\n";    // 直觉
std::cout << INT_MIN << "\n";              // 正确
std::cout << (-INT_MAX - 1) << "\n";       // 推导
```

要求：

- 用 `-Wall -Wpedantic` 编译，观察警告
- 解释为什么 `-2147483648` 在编译期不是单一字面量
- 思考：如果改成 `long long x = -9223372036854775808LL` 会怎样？

**🧪 题 5：扩展规则与 `<cstdint>` 协同**

```cpp
int8_t   c = -1;
uint8_t  u = 0xFF;
int32_t  x = c;     // 符号扩展
uint32_t y = u;     // 零扩展
std::cout << std::hex << x << " " << y << "\n";
```

要求：

- 预测两个输出（一个是 `0xFFFFFFFF` = `-1`，一个是 `0x000000FF` = `255`）
- 反汇编看到 `movsbl` / `movzbl` 两条不同指令
- 把 `int8_t c = -1` 改成 `int8_t c = 0xFF`（隐式转换），观察行为
