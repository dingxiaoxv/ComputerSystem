# §3.4 访问信息

这一节的主线是：**建立读懂一条汇编的稳定心智模型**——寄存器是 CPU 内部的高速临时存储，操作数来自立即数 / 寄存器 / 内存三处，`mov` / `push` / `pop` 是最基本的数据流动方式。看一条指令的核心永远只有三个问题：数据从哪来、到哪去、宽度多少。

---

## 寄存器：同一块硬件的不同宽度视图

**🎯 16 个 64 位通用寄存器**

x86-64 提供 16 个 64 位通用寄存器，每个寄存器都可以按 64 / 32 / 16 / 8 位四种宽度访问：

| 64 位 | 32 位 | 16 位 | 8 位 | 常见用途 |
|------|------|------|------|----------|
| `%rax` | `%eax` | `%ax` | `%al` | 返回值、临时值 |
| `%rbx` | `%ebx` | `%bx` | `%bl` | 被保存寄存器 |
| `%rcx` | `%ecx` | `%cx` | `%cl` | 计数、移位计数 |
| `%rdx` | `%edx` | `%dx` | `%dl` | 第 3 参数 |
| `%rsi` | `%esi` | `%si` | `%sil` | 第 2 参数 |
| `%rdi` | `%edi` | `%di` | `%dil` | 第 1 参数 |
| `%rsp` | `%esp` | `%sp` | `%spl` | 栈顶指针 |
| `%rbp` | `%ebp` | `%bp` | `%bpl` | 栈帧基址 |

**⚠️ 32 位写会清零高 32 位，8/16 位写不会**

这是 x86-64 最容易被忽略的硬性规则：

```asm
movq $-1, %rax        # rax = 0xffffffffffffffff
movl $1, %eax         # rax = 0x0000000000000001  (高 32 位被清零)
movw $2, %ax          # rax = 0x0000000000000002  (高位仍是 0 是因为上一步已经清零)
movb $3, %al          # 只改最低 8 位
```

**🔧 编译器偏爱 `movl` 的原因之一**

很多 C 表达式只涉及 32 位运算，写 `movl` 就自动把高 32 位清零，省去单独的清零指令——这也是 `xorl %eax, %eax` 比 `xorq %rax, %rax` 短的来源。

## 操作数：立即数、寄存器、内存

**🎯 三类操作数**

| 类型 | 例子 | 含义 |
|------|------|------|
| 立即数 | `$8`、`$-16` | 常量直接编码进指令 |
| 寄存器 | `%rax`、`%rdi` | 从寄存器读/写 |
| 内存 | `(%rax)`、`8(%rbp)` | 访问某个地址处的内存 |

**🎯 内存寻址的统一形式**

```text
Imm(rb, ri, s)   →   地址 = Imm + R[rb] + R[ri] * s
```

- `Imm`：常量偏移
- `rb`：基址寄存器
- `ri`：变址寄存器
- `s`：比例因子，只能是 `1/2/4/8`

| 表达式 | 含义 |
|--------|------|
| `(%rax)` | `rax` 指向的内存 |
| `8(%rbp)` | `rbp + 8` 处的内存 |
| `(%rax,%rdx,4)` | `rax + rdx*4` |
| `16(%rax,%rdx,8)` | `rax + rdx*8 + 16` |

这正是数组 `a[i]` 和结构体字段访问在汇编层的标准形式。

**⚠️ 两个高频限制**

- 普通 `mov` 不能直接做内存到内存的搬运
- `%rsp` 不能作为变址寄存器 `ri`

所以下面这种 C 代码必须经过寄存器中转：

```asm
movq (%rdi), %rax    # 先把 *src 读到寄存器
movq %rax, (%rsi)    # 再写到 *dst
```

## `mov` 系列：最基础的数据传送

**🎯 四种宽度后缀**

| 指令 | 宽度 |
|------|------|
| `movb` | 1 字节 |
| `movw` | 2 字节 |
| `movl` | 4 字节 |
| `movq` | 8 字节 |

读一条 `mov` 只需要看三件事：源是谁、目的是谁、几字节。

**🎯 扩展传送：补符号位还是补 0**

当源更窄、目标更宽时，必须明确高位怎么补：

```asm
movsbq %al, %rax      # 符号扩展：8 位有符号 → 64 位
movzbl %al, %eax      # 零扩展：8 位无符号 → 32 位
cltq                  # %eax 符号扩展到 %rax
```

对应到 C 类型：

| C 转换 | 补位方式 |
|--------|---------|
| `char → int` | 符号扩展 |
| `unsigned char → int` | 零扩展 |
| `int → long` | 符号扩展 |
| `unsigned → unsigned long` | 零扩展 |

**判断诀窍**：源类型有符号就符号扩展，源类型无符号就零扩展。

---

## `pushq` / `popq`：栈顶上的特殊数据传送

**🎯 栈向低地址增长**

x86-64 上 `%rsp` 永远指向当前栈顶，栈生长方向是从高地址到低地址。

**🎯 `pushq src` 等价于**

```asm
subq $8, %rsp
movq src, (%rsp)
```

**🎯 `popq dest` 等价于**

```asm
movq (%rsp), dest
addq $8, %rsp
```

注意顺序：`push` 先减 `%rsp` 再写，`pop` 先读再加 `%rsp`。这是函数调用中保存寄存器、保存返回地址、构造栈帧的底层动作。

---

## 易错点

- 写 `%eax` 会自动把 `%rax` 高 32 位清零，写 `%al` / `%ax` 不会，不是"只改低位"那么简单
- 普通 `mov` 不能内存到内存直接搬运，必须经过寄存器中转
- `%rsp` 不能作为变址寄存器，只能作基址寄存器
- 内存寻址里的常量偏移是字节偏移，不是"第几个元素"，乘以元素大小要靠比例因子 `s` 或显式指令
- 扩展传送的关键不是"补位"而是"补什么"——符号扩展和零扩展对应 C 里有符号 / 无符号语义的差别
- `pushq` 不只是"放进栈里"，它还修改了 `%rsp`，会影响后续所有基于 `%rsp` 的寻址

---

## 工程关联

- 反汇编里数组和结构体访问几乎都是 `Imm(rb, ri, s)` 形式，看到就知道是在做有效地址计算，不必逐条死记
- 32 位写自动清零高位这条规则解释了编译器为什么大量用 `movl` / `xorl`——一来指令编码短，二来不需要额外清零
- 看 core dump / GDB `info registers` 时，看到 `%rax` 高 32 位为 0、低 32 位有值，通常是某条 `movl` 或 `addl` 的结果，源代码里是 `int` 而不是 `long`
- ABI 跨模块调用问题（参数寄存器约定、返回值放哪、被保存寄存器）本质都是这个寄存器视图 + `mov` 的组合
- 栈上 `push`/`pop` 的对称结构是函数调用约定的基础；不平衡的 `push`/`pop` 是栈破坏 bug 的直接征兆

## 实验题

**🧪 题 1：观察 32 位写自动清零高 32 位**

```cpp
unsigned long f(unsigned long x) {
    unsigned y = (unsigned)x;
    return y;
}
```

要求：

- `gcc -Og -S` 看汇编
- 解释返回前 `%rax` 高 32 位为什么是 0（没有显式 `xor` 或 `and`）
- 把返回类型改成 `unsigned long` 直接返回 `x`，对比汇编

**🧪 题 2：符号扩展 vs 零扩展**

```cpp
long f1(char x)          { return x; }
long f2(unsigned char x) { return x; }
```

要求：

- 编译查看两者汇编，找出 `movsbq` 和 `movzbl`
- 传入 `0xff` 给两个函数，分别打印结果
- 解释 `f1(0xff) == -1` 而 `f2(0xff) == 255` 的来源

**🧪 题 3：证明 `mov` 不能内存到内存**

```cpp
void copy(long* src, long* dst) {
    *dst = *src;
}
```

要求：

- 反汇编，确认中间一定经过寄存器
- 标出源操作数和目的操作数
- 思考：如果硬件支持内存到内存的 `mov`，编码上会带来什么困难？

**🧪 题 4：手算几个有效地址**

设 `%rax = 0x1000`、`%rdx = 3`，计算：

1. `8(%rax)`
2. `(%rax,%rdx,4)`
3. `16(%rax,%rdx,8)`

要求：

- 写出每个地址的具体数值
- 判断哪个最像 `a[i]` 的访问模式
- 判断哪个最像"结构体里的数组字段"访问

**🧪 题 5：`pushq` / `popq` 对 `%rsp` 的影响**

```cpp
long g(long x) {
    long y = x + 1;
    return y;
}
```

要求：

- 默认 `-O2` 看一遍汇编（大概率没有 `push`/`pop`）
- 加 `-Og -fno-omit-frame-pointer` 再看一遍
- 标出每次 `pushq` / `popq` 后 `%rsp` 的变化值

**🧪 题 6：反推 C 语义**

```asm
movq 8(%rdi), %rax
movq %rax, (%rsi)
```

要求：

- 推测 `%rdi` 和 `%rsi` 各自是什么类型（指针？指针的指针？结构体指针？）
- 写出最可能对应的 C 语句
- 解释为什么第一条不是"把字面值 8 放进 `%rax`"
