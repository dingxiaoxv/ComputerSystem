# §6.1 存储技术

这一节的主线是：**为什么需要存储层次——因为 SRAM、DRAM、闪存、磁盘四种介质的速度/容量/价格差几个数量级，而且 CPU 越来越快、DRAM/磁盘相对越来越慢，这条鸿沟逼着系统把数据分层缓存**。

- SRAM 快但贵（做 cache），DRAM 慢但便宜大（做主存）
- DRAM/SSD/磁盘的物理结构决定了它们的访问特性（随机 vs 顺序、读 vs 写不对称）
- 总线事务是 CPU 和主存之间数据搬运的统一抽象
- 磁盘访问时间被机械的寻道+旋转主导，比 DRAM 慢约 10 万倍
- CPU 和内存的速度差距持续拉大，这是整个第 6 章存在的理由

---

## 两种 RAM：SRAM 和 DRAM

**🎯 核心区别在「一个 bit 用几个晶体管存」**

| 特性 | SRAM | DRAM |
|------|------|------|
| 每 bit 晶体管数 | 6（双稳态触发器） | 1（电容 + 1 晶体管） |
| 需要刷新 | 否 | 是（电容会漏电） |
| 对干扰敏感 | 否 | 是 |
| 速度 | 快（~1 ns 级） | 慢（~10 ns 级，加上行选通更慢） |
| 单价 | 贵（约 100×） | 便宜 |
| 典型用途 | CPU cache、寄存器文件 | 主存、显存 |

**🎯 为什么 DRAM 要刷新**

DRAM 用一个微小电容存电荷表示 1 bit，电容会漏电（约 10~100 ms 就丢失），所以内存控制器必须周期性读出再写回——这就是「刷新」。SRAM 用反馈回路的双稳态电路，只要供电就一直保持，不需要刷新。

**⚠️ 两者都是易失的**

断电后 SRAM 和 DRAM 都会丢数据。「需不需要刷新」和「断电是否保留」是两件事——刷新只解决「通电状态下电容漏电」。

## DRAM 芯片的组织：超单元二维阵列

**🎯 为什么排成二维矩阵而不是一维**

一个 128 Mbit 的 DRAM 若做成一维，需要 log₂(128M) ≈ 27 根地址线。做成 16384 × 8192 的二维阵列，行列地址分时复用同一组地址引脚，只需 14 根地址线——**用「行选通 RAS + 列选通 CAS 两步寻址」换取引脚数量的大幅下降**。代价是访问要两拍。

```
访问一个超单元 (i, j)：
  1. 内存控制器发行地址 i (RAS, Row Access Strobe)
     → 整行 i 被复制到芯片内部的行缓冲区
  2. 发列地址 j (CAS, Column Access Strobe)
     → 从行缓冲区取出第 j 个超单元送出
```

**🎯 行缓冲区是「顺序访问快」的物理根源**

第 1 步把一整行搬进行缓冲区后，**访问同一行的其他列只需再发 CAS，省掉了 RAS 那一拍**。这就是为什么连续访问相邻内存地址（同一 DRAM 行）远快于随机跳访——和后面 cache line、局部性原理是同一套物理逻辑的不同层级体现。

**🎯 内存模块（DIMM）把多个 DRAM 芯片并联**

一条内存条（DIMM）上有 8 个 DRAM 芯片，每个芯片在同一 (i,j) 地址各贡献 8 bit，拼成一个 64 bit 的字。CPU 要的不是某一个芯片的数据，而是 8 个芯片同一位置的横向拼接。

## 非易失性存储：ROM 与闪存

**🎯 ROM 家族（断电不丢）**

| 类型 | 可写性 |
|------|--------|
| ROM | 出厂烧死，只读 |
| PROM | 可编程一次 |
| EPROM | 紫外线擦除，可改约 1000 次 |
| EEPROM | 电擦除，可改约 10 万次 |
| Flash（闪存） | 基于 EEPROM，块级擦除 |

**🔧 固件（firmware）就存在 ROM 里**

BIOS/UEFI、显卡固件、磁盘控制器固件都是存在 ROM/Flash 中的程序，开机时 CPU 第一条指令就来自 ROM。这是「上电后还没有操作系统时，代码从哪来」的答案。

---

## 总线与访问主存：读/写事务

**🎯 总线事务是 CPU↔主存数据搬运的统一抽象**

CPU 通过「总线」连接主存，一次数据传输叫一个「总线事务」：

```
读事务（load，如 movq A, %rax）：
  1. CPU 把地址 A 放上系统总线
  2. I/O 桥转发到内存总线
  3. 主存读出 A 处的数据放上总线
  4. CPU 从总线读入 %rax

写事务（store，如 movq %rax, A）：
  1. CPU 把地址 A 放上总线，主存等待
  2. CPU 把数据放上总线
  3. 主存从总线读入并写到 A
```

**🎯 总线带宽是十进制单位**

这正好接上 USB 的讨论：总线/接口速率（PCIe、内存总线、USB）一律用十进制 M=10⁶、G=10⁹，因为它们本质来自时钟频率。只有内存「容量」、cache 大小、页大小才用二进制 2²⁰、2³⁰。

| 量 | 单位约定 |
|----|----------|
| DDR4-3200 带宽 25.6 GB/s | 十进制 10⁹ |
| 内存条容量 16 GiB | 二进制 2³⁰ |
| 页大小 4 KiB | 二进制 2¹⁰ |

## 磁盘构造与容量

**🎯 几何结构**

磁盘 = 多个盘片(platter)叠放，每片两面(surface)，每面分成同心圆磁道(track)，每条磁道分成扇区(sector)，扇区间有间隙(gap)。所有盘面上半径相同的磁道组成一个柱面(cylinder)。

**🎯 容量公式**

```
容量 = 字节/扇区 × 平均扇区/磁道 × 磁道/面 × 面/盘片 × 盘片/磁盘
```

例：512 字节/扇区，平均 300 扇区/磁道，20000 磁道/面，2 面/盘片，5 盘片：

```
512 × 300 × 20000 × 2 × 5 = 30,720,000,000 ≈ 30.72 GB（十进制 GB）
```

**⚠️ 磁盘厂商的 GB 是十进制 10⁹**

「500 GB 硬盘」装到系统里显示 ~465 GiB，不是缺斤少两——厂商按 10⁹ 标，操作系统按 2³⁰ 算，差比是 10⁹/2³⁰ ≈ 0.931。这又是十进制 vs 二进制单位的经典坑。

---

## 磁盘访问时间：被机械动作主导

**🎯 三部分相加**

```
T_access = T_seek（寻道） + T_rotation（旋转延迟） + T_transfer（传输）
```

| 分量 | 含义 | 典型值 |
|------|------|--------|
| 寻道时间 | 磁头臂移到目标磁道 | ~3~9 ms |
| 旋转延迟 | 等目标扇区转到磁头下 | 平均 = 半圈时间，7200 转约 4.17 ms |
| 传输时间 | 读出一个扇区 | 远小于上面两者 |

**🎯 一次随机磁盘访问 ≈ 10 ms 量级**

对比 DRAM 的 ~50 ns，磁盘慢约 **20 万倍**。这就是「换页到磁盘（major fault）会让程序卡死」的根本原因——一次缺页换入抵得上几十万次内存访问。

**⚠️ 旋转延迟取「平均」是半圈不是整圈**

目标扇区可能恰好在磁头下（0）也可能刚转过去（一整圈），期望值是转半圈的时间，即 `T_rotation_max / 2`。

## 逻辑磁盘块与 I/O 总线

**🎯 磁盘对外暴露的是「逻辑块」抽象**

操作系统看不到柱面/磁道/扇区这些物理几何，磁盘控制器(固件)把它们映射成一维的逻辑块号(LBA, Logical Block Address) 0,1,2,...。`(柱面,磁道,扇区) ↔ 逻辑块号` 的翻译由磁盘内部完成，对 OS 透明。

**🎯 I/O 设备挂在 I/O 总线上**

```
CPU ── 系统总线 ── I/O桥 ── 内存总线 ── 主存
                     │
                  I/O总线（PCIe / SATA / USB / ...）
                     ├── 磁盘控制器 → 磁盘
                     ├── USB 控制器 → 键鼠/U盘
                     └── 网卡 / 显卡
```

USB、SATA、PCIe 都是 I/O 总线标准——前面算的 USB 625 MB/s、磁盘 SATA 600 MB/s 都是这一层的带宽。

## 固态硬盘 SSD

**🎯 基于闪存，无机械部件**

SSD 由闪存芯片 + 闪存翻译层(FTL, 类似磁盘控制器)组成。没有磁头和盘片，所以**随机访问和顺序访问的差距远小于机械磁盘**，随机读延迟约几十 µs（比磁盘快约百倍）。

**⚠️ 读写严重不对称，且有寿命**

| 操作 | 特点 |
|------|------|
| 读 | 快，~25 µs，可按页（4 KB）随机读 |
| 写 | 慢，且**不能原地改**——必须先「擦除」整个块（~128 页），再写 |
| 擦除 | 最慢，块级，且每块可擦写次数有限（~10 万次后磨损报废） |

写慢的根因：闪存写之前必须擦除，而擦除是块级的。FTL 用「磨损均衡(wear leveling)」把写分散到各块，避免某块被写穿。这就是为什么 SSD 顺序写远快于随机小写，以及为什么 SSD 用久了会变慢(可擦块变少)。

**🔧 这解释了日常现象**

- SSD 的 4K 随机写 IOPS 是数据库选型关键指标
- TRIM 命令让 OS 告诉 SSD 哪些块可回收，提升后续写性能
- 数据库 WAL/日志「顺序追加写」设计正是为了迎合闪存/磁盘都擅长顺序写的特性

## 存储技术趋势：CPU-内存鸿沟

**🎯 三种技术的演进方向**

- SRAM、DRAM、磁盘的「单位容量价格」都在指数下降，容量指数上升
- 但**速度提升慢得多**：DRAM 和磁盘的访问时间几十年只改善了几倍到几十倍，远跟不上 CPU
- CPU 时钟从 MHz 涨到 GHz（千倍），DRAM 延迟只缩短到约 1/10

**🎯 这就是整个第 6 章的存在理由**

CPU 和主存之间的速度差距（the processor-memory gap）越拉越大，单纯加快 CPU 没用，数据取不上来。解决办法就是利用**局部性**，在 CPU 和主存间插入 SRAM 高速缓存——这是 §6.2~6.7 要展开的核心。

---

## 易错点

- SRAM 和 DRAM 都是易失的，断电都丢数据；「需要刷新」只是 DRAM 因电容漏电的额外负担，不等于「断电能保留」
- DRAM 二维阵列的目的是减少地址引脚，不是为了存更多——行列地址分时复用同一组引脚
- 总线带宽、磁盘/内存「速率」用十进制 10⁶/10⁹；内存「容量」、cache、页大小用二进制 2²⁰/2³⁰，两者别混
- 磁盘平均旋转延迟是转「半圈」的时间，不是整圈
- 磁盘慢的主因是机械寻道+旋转（毫秒级），不是数据传输；传输本身很快
- SSD 不能原地改写，写之前必须块级擦除，所以随机小写慢、且有擦写寿命上限
- 逻辑块号是磁盘控制器对外的抽象，OS 看不到物理柱面/磁道/扇区

## 工程关联

- `dmidecode -t memory` 看 DRAM 类型/速率（DDR4-3200 等），`lshw -class memory` 看内存模块布局
- 内存带宽用 `mbw`、`stream` 基准测试，对应 DRAM 行缓冲区命中率——顺序访问比随机访问带宽高数倍
- `lsblk`、`smartctl -a /dev/sda` 看磁盘/SSD 健康度，SSD 的 `Wear_Leveling_Count`、`Total_LBAs_Written` 直接对应擦写寿命
- `iostat -x 1` 的 `await`（平均 I/O 等待）在机械盘上由寻道+旋转主导，是判断磁盘瓶颈的核心指标
- `fio` 做 4K 随机读写 IOPS 测试，机械盘随机 IOPS ~100、SATA SSD ~数万、NVMe ~数十万，差距正源于本节的物理结构
- 缺页换入磁盘（major fault，`perf stat` 可见）一次约 10 ms，等于数十万次内存访问——这是 swap 抖动让系统假死的根源
- lscpu 看 cache 层级（L1/L2/L3 都是 SRAM），容量从 KiB 到几十 MiB，正是「SRAM 贵所以小、DRAM 便宜所以大」的体现

## 实验题

**🧪 题 1：观测本机存储层次的真实参数**

要求：

- `lscpu | grep -i cache` 看 L1/L2/L3 大小，确认逐级变大（SRAM 越靠近 CPU 越小越快）
- `sudo dmidecode -t memory | grep -iE 'speed|size|type'` 看 DRAM 类型和速率
- `lsblk -d -o NAME,ROTA,SIZE,MODEL`，`ROTA=1` 是机械盘、`ROTA=0` 是 SSD
- 把三层（SRAM cache / DRAM / 磁盘）的容量和延迟列成一张表，直观感受数量级差距

**🧪 题 2：顺序 vs 随机磁盘访问对比**

用 `fio` 在同一块盘上分别跑顺序读和 4K 随机读：

```bash
fio --name=seq  --rw=read     --bs=1M --size=1G --filename=testfile
fio --name=rand --rw=randread --bs=4k --size=1G --filename=testfile
```

要求：

- 对比两者的带宽(MB/s)和 IOPS
- 在机械盘上随机读应远慢于顺序读，解释这正是寻道+旋转延迟在作怪
- 若手头是 SSD，对比差距会小很多，解释为什么（无机械寻道）

**🧪 题 3：手算磁盘容量与访问时间**

给定参数：512 字节/扇区、400 扇区/磁道（平均）、10000 磁道/面、2 面/盘片、4 盘片；转速 7200 RPM；平均寻道 5 ms；最大传输速率 100 MB/s。

要求：

- 算磁盘总容量（十进制 GB）
- 算平均旋转延迟（提示：半圈时间）
- 算读一个 512 字节扇区的传输时间
- 把三者相加得平均访问时间，确认寻道+旋转占绝对主导

**🧪 题 4：验证厂商容量与系统显示的差异**

要求：

- 找一块标称容量已知的盘（如「256 GB」SSD），`lsblk -b` 看字节数
- 把字节数分别除以 10⁹ 和 2³⁰，确认厂商标称对应前者、系统 `df -h`/文件管理器显示对应后者
- 算出 0.931 这个比值，理解「500G 盘只有 465G 可用」不是缩水

**🧪 题 5：观测 swap 换页的磁盘代价**

要求：

- `vmstat 1` 跑起来，观察 `si`（swap in）/`so`（swap out）两列
- 写个程序申请并触摸超过物理内存的大数组，触发 swap，观察 si/so 飙升、系统卡顿
- `perf stat -e major-faults ./prog` 看 major fault 次数
- 用「一次 major fault ≈ 10 ms」估算换页消耗的总时间，理解为什么内存不足会让系统假死
